# manga-scan-binarize

漫画のスキャン画像を、網点（スクリーントーン）を保ったまま綺麗に2値化するツール。
ベクトル化（potrace / Illustrator の画像トレース）の前処理を想定している。

> Binarize scanned manga pages while preserving halftone screentones.
> Handles background/illumination correction, spread splitting, margin trimming,
> and outputs 1-bit PNG / TIFF(G4) / PBM ready for potrace.

## インストール

```sh
python3 -m venv .venv
./.venv/bin/pip install -r requirements.txt
```

`mb` は `.venv` があればそれを使い、無ければ `python3` を呼ぶだけのラッパー。

## 使い方

```sh
./mb 原稿.tif -o 原稿_bw.png            # 1枚
./mb scans/*.tif -O out/                # 一括
./mb 見開き.jpg -O out/ --split --trim  # 見開きを2ページに分割し余白を落とす
./mb 原稿.tif --compare cmp.png         # 設定の効き比べシートを作る
./mb 原稿.tif -O out/ --format pbm      # potrace に渡せる形式で出力
```

まず `--compare` で1ページ見て `--k` / `--sharpen` を決めるのが速い。中央（`--crop X Y`
で位置指定）を等倍で切り出し、8通りの設定を並べたシートを作る。

## 処理の流れ

1. **フラットフィールド補正** — 明るい側の画素だけに低次の多項式曲面を当てて紙の地色を
   推定し、割り算で地を均一な白にする（`--bg-mode fit`、既定）。
2. **アンシャープマスク** — 網点と線のエッジを立てる。
3. **しきい値** — 既定は大域 Otsu。地が均一になっていれば、大域しきい値のほうが
   網点の濃度を正確に再現できる。
4. **ゴマ塩除去 / ピンホール埋め** — 面積2px未満だけ。網点は消さない。

### 地色推定にクロージングを使わない理由

よくある実装はモルフォロジーのクロージングで背景を推定するが、これは
**ボケた広いトーン面の中では「そのトーンの明るい部分」を紙と誤認して、トーンごと
白く飛ばす**。実際の300dpiスキャンで、平均濃度27.5%のトーン面が黒率9.7%まで
飛んだ。明るい側の画素だけに多項式曲面を当てる `--bg-mode fit` はこれを起こさない。

半径を大きくすればトーンは飛ばなくなるが、今度は綴じ目の急な影に追従できなくなる。
多項式fitは両立する（下表）。

### 精度

合成テスト原稿（600dpi、網点3段、細線、小文字、JPEG劣化あり。`tools/make_test.py` で生成、
`tools/metric.py` で測定）での画素一致率:

| 地色推定 | 通常 | 綴じ目の影が強い |
|---|---|---|
| 多項式fit（既定） | **99.95%** | **99.87%** |
| クロージング 半径120 | 99.08% | 99.15% |
| クロージング 半径600 | 99.94% | 93.71% |
| 補正なし | 99.78% | 89.34% |

網点の濃度再現（既定設定、通常の原稿）:

| | 元 | 出力 |
|---|---|---|
| トーン15% | 15.9% | 15.8% |
| トーン35% | 36.3% | 36.2% |
| トーン60% | 60.0% | 60.0% |

```sh
./.venv/bin/python tools/make_test.py          # test_scan.jpg を生成
./mb test_scan.jpg -o out.png --dpi 600
./.venv/bin/python tools/metric.py out.png     # 一致率を測る
```

## 主なオプション

| オプション | 効果 |
|---|---|
| `--dpi 600` | 解像度。窓サイズ等を自動スケール。省略時はファイルのDPI、無ければ600 |
| `--split` | 見開き1枚を綴じ目で分割（右ページ `_r`・左ページ `_l`） |
| `--trim` | 周囲の白余白を落とす |
| `--deskew` | コマ枠・文字行から傾きを推定して補正 |
| `--format png\|tif\|pbm` | tif は G4圧縮で軽い。pbm は potrace が直接読める |
| `--sharpen 1.2` | 網点が潰れ気味のとき上げる。0で無効 |
| `--method sauvola --k 0.20` | 局所しきい値。地色補正で取り切れないムラがある原稿用。`--k` 小=黒が増える |
| `--method fixed --k 130` | 固定しきい値 |
| `--bg-mode close --bg-radius 600` | 地色推定をクロージングに切り替える |
| `--tone auto` | 網点が解像できている所はしきい値、ボケた所だけディザ |
| `--tone dither` | 中間調を全部誤差拡散で打ち直す |
| `--preblur 3` | しきい値前にぼかして網点を潰す。`--method fixed` と併用で線画だけ抽出 |
| `--round-dots` | 3x3メディアンで1pxのトゲを落とす（600dpi以上の原稿限定、下記） |
| `--layers` | 線画レイヤーとトーンレイヤーを別ファイルに分離（実験的） |

## 解像度と `--tone` の選び方

`--tone keep`（既定）は元の網点をそのまま2値にする。これが成立するのは**網点1個が
数ピクセル以上に解像されている場合**。300dpi のスキャンでも、3.2pxピッチの線トーンは
連続した線として残せた。

網点がグレーに平均化されてしまっている画像では、`keep` でしきい値を切ると干渉縞が
まだら模様になって出る。その場合は `--tone dither`。ただし網点は再現ではなく
**作り直し**になる。

`--round-dots` は3x3メディアンなので、**網点が3px以上（=600dpi以上）でないと
トーンごと消える**。300dpi の原稿には使わないこと。

## ベクトル化するときの注意

potrace は PNG を読めない（pnm/bmp のみ）。`--format pbm` で出力してから渡す:

```sh
./mb 原稿.png -O out/ --dpi 300 --split --trim --format pbm
potrace -s -t 2 -a 1.3 -O 0.4 out/原稿_r_bw.pbm -o 原稿_r.svg
```

potrace 1.16 での実測（300dpiの見開きスキャン、1ページ1101x1701、2値化画像を基準）:

| オプション | 一致率 | アンカー | SVG |
|---|---|---|---|
| `-t 0 -a 1.0 -O 0.2`（忠実） | 97.4% | 25,153 | 1.1MB |
| `-t 2 -a 1.3 -O 0.4`（軽量） | 96.6% | **8,996** | 566KB |

軽量側はアンカーが1/3になっても一致率の低下は0.8ptだけ。`mkbitmap -x -s 2` を挟む
定番手順は、この種の原稿では一致率が下がってファイルが倍になるだけで効果がなかった。

### グレースケールのままトレースしない

Illustrator の画像トレースを「グレースケール」でスキャン原画にかけると再現性が落ちる。
同じ領域を2値化画像基準で比較した実測:

| 手法 | 一致率 |
|---|---|
| 2値化してから白黒トレース | **97.3%** |
| グレースケールのままトレース | 85.9% |

グレースケールトレースは数段階のグレーに量子化してから同濃度の領域を面として囲むので、
300dpiでは1〜2pxの網点は消えるか隣とくっついてべったりした塊になり、1pxの細線は
周囲と同じ濃度帯に量子化されて線として拾われない。先に2値化しておけば量子化する余地が
なく、トレースは輪郭を追うだけになる。

Illustrator で使うなら 2値化済みPNGを「**白黒**」プリセット、しきい値128、パス:忠実、
ノイズ:1px でトレースする。

### 300dpi での限界

`--preblur 3 --method fixed --k 100 --sharpen 0` で線画だけ抜くとアンカーは1/5に
減ってトーンも完全に消えるが、**細線や小さい文字も一緒に消える**。300dpi では
細線(1px)と網点(1-2px)が同じ大きさなので、ぼかしで両者を分離するのは原理的にできない。
線画だけを綺麗に取り出したいなら600dpi以上でスキャンし直すしかない。
